# DeepSee 当前应用全流程图设计

日期: 2026-08-12
状态: 已确认并直接实施

## 目标

生成一张兼顾产品阅读与工程实现的端到端流程图。图的主线应让非开发者理解用户如何从 DeepSee Web 输入文本或图片并获得回复；工程层应让开发者看清本地网关中的鉴权、请求校验、视觉处理、缓存、DeepSeek 推理、流式响应和请求追踪。

## 事实基线

流程以当前可运行代码为准:

- DeepSee Desktop `main` 提交 `7586ffd`: React Web 已通过 `HttpDesktopBridge` 接入本地 DeepSee 网关。
- DeepSee 核心集成工作树提交 `ff80bdd`: 提供静态网站托管、健康检查、本地 API 鉴权、OpenAI 兼容聊天、视觉缓存、请求追踪和管理端点。
- Tauri 进程管理、Codewhale 执行和会话持久化尚未落地，不进入现状主图。

## 图表结构

采用横向主流程与纵向分层相结合的单图结构，包含五个泳道:

1. 用户与客户端: DeepSee Web、OpenAI 兼容客户端，以及文本、图片、模型和视觉模式输入。
2. Web 交互层: React 会话状态、附件 Data URL、完整消息历史和 `HttpDesktopBridge`。
3. 本地网关层: FastAPI 静态托管、健康检查、CORS、本地 public/admin key 鉴权、32 MiB 请求体上限、协议解析和参数校验。
4. 组合推理层: 纯文本直通；带图消息进入图片安全管线、视觉模式路由、进程内缓存和可插拔视觉后端，再把视觉分析注入原消息历史。
5. 输出与观测层: DeepSeek Chat Completions、视觉分析前置元数据、文本与工具调用增量、SSE 完成事件、Web 渲染，以及 trace ID、延迟、路由、缓存命中和错误类型记录。

## 主流程

用户在 Chat 或 Playground 输入问题，可选择一张图片、模型和 `auto`、`ui` 或 `general` 视觉模式。Web 将完整对话历史和图片 Data URL 交给 `HttpDesktopBridge`，后者调用 `POST /v1/chat/completions`，请求流式响应并要求返回视觉分析元数据。

请求先经过 CORS、鉴权、追踪和请求体上限，再解析 OpenAI 消息及受支持参数。没有图片时，消息历史直接转发给 DeepSeek。带图时，每张图片先经过 data/http 输入归一化、SSRF 与重定向检查、字节/像素/格式限制，然后按视觉模式调用 OpenAI-compatible、Anthropic 或 Gemini 视觉后端。视觉结果按图片与问题生成缓存键；命中时复用，未命中时写入进程内缓存。分析文本替换对应图片内容并注入消息历史，随后统一交给 DeepSeek。

DeepSeek 的原生 completion 或 SSE chunk 由网关保留并转发。若请求包含视觉扩展头，网关先发 `vision_analysis`，再发回答文本和工具调用增量，最后发送 `[DONE]`。Web 将事件转换为 `start`、`analysis`、`chunk`、`tool_calls` 和 `complete`，实时更新消息视图；用户可以中止请求，中止通过 `AbortController` 取消浏览器 fetch。

## 旁路与异常

健康检查不需要认证。公共聊天端点使用 public key，管理追踪端点使用 admin key。配置缺失返回 503，鉴权失败返回 401，畸形请求或不安全图片返回 400，请求体超限返回 413，上游视觉或 DeepSeek 失败返回 502；流式阶段的上游错误通过 SSE error chunk 返回。

每个请求都生成 trace ID。响应结束或流关闭后记录状态、总延迟、逻辑路由、是否带图、图片数量、视觉缓存命中数、上游模型和错误类型。视觉分析只存字符数与摘要指纹，不在追踪记录中保存完整内容。

## 视觉编码

- 蓝色: 用户输入与 Web 客户端。
- 紫色: 本地网关与协议处理。
- 青绿色: 图片、安全和缓存。
- 橙色: 外部视觉模型与 DeepSeek 上游。
- 绿色: 正常输出与界面呈现。
- 红色虚线: 错误返回和中止路径。
- 实线箭头: 同步主流程或确定的数据传递。
- 虚线箭头: 观测、缓存复用、错误与控制旁路。

## 验收标准

图中应能在一次浏览中回答以下问题: 用户从哪里发起请求；纯文本和图片请求在哪里分叉；图片经过哪些安全与视觉步骤；视觉分析如何进入 DeepSeek；流式响应如何回到界面；鉴权、错误和追踪发生在哪里；哪些能力属于当前实现而非未来规划。
